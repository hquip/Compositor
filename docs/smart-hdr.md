# Protected raster objects and float32 HDR in preview 0.10.0

## Raster smart objects

**Objects → Convert to smart object** retains the embedded original PNG or HDR TIFF, its filter stack and source dimensions. Affine placement/scale/rotation changes keep these original pixels. Shrink followed by enlargement therefore renders from the retained source rather than the smaller intermediate cache. Reset object transform restores the conversion's placement; image-size operations retain the source.

Copies share an object UUID inside a project. Replace embedded PNG preserves each copy's transforms and individual masks/filter parameters while changing their sources together. Make object independent splits that relationship. Replacing a PNG retains its sixteen-bit source when provided. Undo restores source bytes and appearances together.

Edit embedded content opens a content tab using the unfiltered embedded source. Apply content to parent renders that tab and updates the shared parent copies as one parent undo step. The parent must remain open and its source must still match the content tab's starting source. PNG content is raster data: the child tab's layer tree is flattened when applied. Its temporary parent association is a session-only link; recovered/saved content tabs can be reopened as ordinary projects but do not automatically reconnect to a parent after restart. Nested editable `.comp`/PSD objects, external linked files, vector/PDF source rendering and nondestructive perspective warps are not yet supported.

Ordinary pixel painting/destructive filters refuse protected source layers. Use editable filters, the content tab or explicit Rasterize. Layer and filter masks remain independent and editable. Rasterize smart object removes the protection, original source and filter parameters after the explicit choice; HDR requires its own explicit display-rasterization step.

Compatible PSD/PSB delivery writes placed raster-layer metadata and embedded PNG data. Individual enabled filter stacks are baked into embedded content for that derivative; the `.comp` original stays editable. Layer effects require the existing raster delivery path. Complex incoming Photoshop Smart Objects still use their conversion/cache fallback, and Photoshop application acceptance is outstanding.

## Float32 HDR

Import float32 HDR accepts a single, uncompressed classic TIFF with interleaved IEEE float32 RGB/RGBA or grayscale samples and top-left orientation. Assign its linear input space from sRGB, Rec.2020, P3-D65, ACEScg or ACES2065-1; embedded ICC profiles are not converted by this import. Preview 0.9.0 also imports/exports a bounded subset of [OpenEXR](openexr.md), including HALF/FLOAT, ZIP/ZIPS/uncompressed, channel-group selection, color metadata and offset windows. Preview 0.10.0 adds configurable linear HDR working spaces, retained PIZ/tiled/multipart/Deep EXR and extended HDR display; see [OpenEXR](openexr.md). Negative RGB and highlights above one are retained, within the finite ±1,000,000 intensity limit. Source files are stored as canonical float32 RGBA TIFF after input interpretation/conversion, with independent filter masks. TIFF stores the IEEE format in `SampleFormat` and the width in `BitsPerSample`, as specified by the [TIFF 6.0 specification](https://www.itu.int/itudoc/itu-t/com16/tiff-fx/docs/tiff6.pdf).

The HDR pipeline supports Exposure (including offset/gamma), Gaussian Blur, Motion Blur, Invert, Add Noise, Color Balance and Black & White. Color tools operate in the fixed linear RGB space, so their appearance is not a declaration of Photoshop parameter/rendering parity. Blend modes are Normal, Multiply, Darken, Lighten, Screen, Linear Dodge (Add), Difference, Subtract and Divide. Groups, layer opacity, masks and clipping use floating-point alpha composition. Unsupported document adjustments/blends/effects require an SDR workflow or explicit rasterization instead of silently clipping the HDR data.

HDR display preview provides exposure and Reinhard/Clip tone mapping. SDR is the display fallback. Preview 0.10.0 adds conditional extended WebGPU HDR output; this is not HDR10/PQ video mastering or fixed-nits calibration. Preview settings and cached PNGs do not replace float source values. Export float32 HDR TIFF writes the linear composite, including layer transforms/masks, retaining highlights above one. PNG/JPEG and explicitly flattened Photoshop output are tone-mapped derivatives. ICC print workflows require explicitly converting/rasterizing the displayed HDR content first; this pipeline is not a general floating-point ICC engine.

HDR source import is bounded to 4 MP on phones and 16 MP on desktop. Full HDR composite output is bounded to 16 MP; interactive previews are bounded to 768 pixels on the longer document side. Float sources count four units per pixel toward aggregate budgets, and phone archives still have their existing byte budget. This release does not provide tiled/universal large-document performance, universal OpenEXR or Radiance RGBE input, HDR exposure-bracket alignment/merging, every HDR filter/blend mode, native HDR display delivery or full float-color ICC/CMYK editing.

## Compatibility and native acceptance

New saves use **format 16**; versions 1–15 remain readable. Native Mac source preserves float TIFF bytes, smart identity, caches, filters and masks on ordinary saving/duplication/canvas changes. Its native protected-source pixel edits are blocked until explicit preview rasterization. It uses the eight-bit cache for display; shared HDR compositing and native cached Mac display can differ. Native Mac source editing and Xcode/device acceptance remain outstanding, as does native iOS compilation. No repository was pushed and no physical Android device was changed.
